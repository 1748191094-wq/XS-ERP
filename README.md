# 服务平台门店服务与售后管理平台

首次安装、单机启动和局域网启动请先看 [START_HERE.md](START_HERE.md)。

这是在原有报价程序基础上演进的模块化维修管理系统。本交付仅包含脱敏源码，不包含旧数据库、历史 PDF、Excel、日志、附件或其他业务数据；首次启动时会在本机数据目录创建新数据库。

详细审计结论见 [PROJECT_AUDIT.md](docs/PROJECT_AUDIT.md)。
报价 PDF 与邮件字体的商用审计见 [FONT_LICENSING.md](docs/FONT_LICENSING.md)。

## 已完成功能

- 客户管理：空手机号、填写后唯一性检查、企业微信预留字段。
- 数码设备：客户绑定、序列号可重复留存二手流转记录、临时设备标记。
- 维修工单：完整状态枚举、状态历史、工单集中工作台、完成后自动回访。
- 报价：人工项目修改、折扣、人工费、运费、多版本历史、客户确认、报价与收款分离。
- PDF：报价单、检测报告、完成报告；中文字体自动发现、用户输入转义、临时文件原子替换。
- 库存：物料、价格、安全库存、入库/出库/维修领料/退料类型、维修领料自动扣减、防负库存、变动前后数量审计。
- 财务：收入、支出、退款；按实际收款、费用和领料成本重算工单毛利润。
- 附件：本地统一存储、安全文件名、大小和扩展名限制、SHA-256。
- 日志：上传、后台任务记录、进度、错误保存、结构化 CSV 解析与 DJI Flight Record v13 可选官方适配。
- 规则分析：电池压差与 GPS 星数示例规则；所有结果要求人工确认。
- 技术插件：DJI DAT 明确安全保留为未启用；PX4 ULog、ArduPilot BIN 提供官方开源库的可选适配；不伪造结果。
- 外部接口：企业微信、顺丰、手工标定 Provider 与 Mock 实现。
- 标定、物流、诊断、系统设置、回访任务页面和 API。
- SQLAlchemy 2 数据模型、Alembic 基线迁移、安全旧库迁移、演示数据、端到端测试。

## 第三阶段新增

- 首次使用自助创建管理员，不内置默认账号或弱密码；初始化时必须填写商标/品牌名称，保存后用于客户端、管理端、邮件和报告文案。
- 登录会话使用 HttpOnly、SameSite=Strict Cookie，所有写操作同时校验 CSRF Token。
- 密码只保存 PBKDF2-SHA256 强哈希，登录名匹配不区分大小写。
- 角色包括管理员、门店经理、前台、维修工程师、财务、库管和只读查看。
- 财务、库存、系统设置、账号管理、操作审计和数据备份实施后端权限隔离，不能只靠隐藏菜单绕过。
- 所有新增、修改、发送、上传、退出等操作写入审计记录，但不记录密码、SMTP 授权码等秘密。
- 管理端增加“账号管理”“操作审计”“数据备份”页面。
- SQLite 备份使用在线备份 API，完成后执行 `integrity_check` 和 SHA-256 校验；提供管理员下载和重新校验。
- 提供停机恢复脚本，恢复前自动保留当前数据库保护副本。

详细说明见 [PHASE3_ANALYSIS.md](docs/PHASE3_ANALYSIS.md)。

- 商城订单详情新增可视化流转进度、配送/支付/收件信息、物流单号复制和刷新操作；只展示真实当前状态，不伪造缺失的历史节点时间。
- 客户端支持跟随系统、浅色和深色模式；设置入口位于“我的 → 设置”，用户选择会保存在当前浏览器。
- 个人中心四项统计始终显示数字；在旧接口未返回汇总字段时，会根据订单、维修和回收数量安全计算，缺失值按 `0` 显示。
- 后台“库存管理”增加“客户端展示”开关。现有及新建物料默认是后台专用，只有显式允许展示的物料才能关联商城 SKU。

- “旧机报价”支持下载 `.xlsx` 模板并批量导入。品牌、型号、版本相同则更新，其余新增；整表先校验，任何一行错误时本批次不写库。

## 安装与启动（Windows PowerShell）

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

也可用统一主机启动器选择模式：

```powershell
python scripts\run_host.py --standalone
```

- 客户端：`http://127.0.0.1:8000/client`

### 客户端前端开发

### 邮件配置

默认 `.env.example` 使用安全的 Mock 模式，不向外发送。确认配置后：

```env
EMAIL_MODE=smtp
SMTP_HOST=smtp.feishu.cn
SMTP_PORT=465
SMTP_USERNAME=sender@example.com
SMTP_PASSWORD=邮箱授权码
SMTP_FROM_EMAIL=sender@example.com
SMTP_FROM_NAME=
```

端口 `465` 使用 SMTP SSL；其他端口根据 `SMTP_USE_STARTTLS` 决定是否启用 STARTTLS。管理员也可以在“系统设置 → 发件端服务设置”中像原程序一样直接修改，无需编辑 `.env`。Windows 上的授权码使用 DPAPI 本机加密，保存后不会回显。

## 迁移旧数据

迁移脚本首先完整复制 `quotation.db`，再把客户、设备、工单、报价项目和 PDF 附件导入新库：

```powershell
python scripts\migrate_legacy.py --source quotation.db
```

输出位置：

- 旧库备份：`backups/`
- 无法自动映射和孤立文件报告：`migration_reports/`

迁移规则：

- 不修改、不删除旧库。
- “无”“查询”等序列号转为临时设备编号。
- 旧报价不自动记为收款。
- 旧物料没有采购成本，历史成本不会凭空推断。
- 重复运行默认跳过，只有显式 `--force` 才重新扫描；目标库已存在的报价仍会跳过。


每日自动备份可在页面设置，Windows 计划任务安装命令为：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_backup_task.ps1 -Time 02:30
```

恢复必须先停止应用。脚本会先为当前数据库建立保护副本，只有明确填写确认文本才会执行：

```powershell
python scripts\restore_backup.py --backup "backups\system\repair-management-时间.db" --confirm RESTORE
```
