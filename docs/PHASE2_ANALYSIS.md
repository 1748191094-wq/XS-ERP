# 第二阶段分析与完成情况

## 第二阶段目标

第二阶段重点不是引入更多基础设施，而是恢复旧程序的高频操作效率，并把邮件、日志分析和报价流转纳入可追踪的新架构。

## 已完成

### 1. 快捷录入工作台

- 新增独立导航入口和仪表盘快捷按钮。
- 同一页面填写客户、电话、邮箱、微信、企业信息、设备、序列号、故障、收机状态、附件和报价。
- 客户优先按手机号复用，其次按邮箱复用；不会因重复录入创建多个客户。
- 序列号已存在且属于其他客户时明确拒绝，不静默改绑。
- 序列号留空时建立可追踪的临时设备。
- 客户、设备、工单、状态历史和报价在同一数据库事务中创建。
- 报价项目支持库存项目带价和自定义项目、人工费、运费、优惠、成本和实时合计。
- `Idempotency-Key` 防止页面重试造成重复工单和重复邮件。

### 2. 邮件功能

- 客户表新增邮箱字段，旧 `customer_email` 具备迁移映射。
- 保留旧程序的 SMTP SSL / STARTTLS 能力，改为独立 `EmailService`。
- PDF 报价单作为附件，邮件正文对客户输入进行 HTML 转义。
- 发信邮箱、SMTP 地址、端口和授权码可像原程序一样在管理界面填写。
- Windows 使用 DPAPI 对授权码做本机加密；页面、API、审计记录均不回显授权码。
- 默认 Mock 模式完整验证邮件构建和附件，但明确不外发。
- 每次发送建立 `EmailDelivery` 和 `TaskRecord`，保存排队、发送、成功、失败和错误信息。
- 报价页面可单独补发，邮件记录页面可查看状态。

### 3. 日志规则分析

- Battery：电芯压差和相邻采样电压快速下降。
- Motor：多电机转速差异持续超阈值。
- ESC：错误、状态和告警字段异常。
- IMU：姿态误差峰值超阈值。
- GPS：有效采样中卫星数持续偏低。
- Compass：指南针错误或磁干扰超阈值。
- FlightEvent：失联、链路中断、自动返航和 RTH 事件。
- 阈值集中配置，诊断结果继续要求人工确认。

## 已验证

- 快捷录入一次创建客户、设备、工单和报价。
- 同一重复提交标识不会重复建单或发信。
- 快捷录入自动生成 PDF。
- Mock 邮件任务最终进入 `sent`，且提供方明确为 `mock`。
- 七类规则可由结构化 CSV 触发并写入诊断表。
- 浏览器中快捷录入布局、导航、实时客户/设备/故障预览正常，无控制台错误。

## 仍受外部条件限制

- 当前没有真实邮箱授权码，未向外部地址做真实 SMTP 投递测试。
- 企业微信和顺丰仍需要正式账号、权限及沙箱联调。
- DJI DAT 与自动云台标定的官方能力边界已经整理；详见 `DJI_RESEARCH.md`，真机自动化仍需要目标机型和硬件测试条件。
- 日志规则虽已实现，但不同工具导出的列名仍需真实样本建立映射。

## 建议的第三阶段

1. 增加登录、角色权限、敏感操作审计和会话安全。
2. 使用专用测试邮箱验证实际 SMTP 投递、退信和超时重试。
3. 导入脱敏真实日志，建立列名适配器、基准数据和阈值回归测试。
4. 完成采购、供应商、库存批次、盘点和成本核算。
5. 使用企业微信和顺丰沙箱账号实现真实 Provider。
6. 增加自动备份、恢复演练和 PostgreSQL 部署。
