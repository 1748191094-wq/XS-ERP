# 维修申请：提交前检查附件并逐项调整

起点 b115a47，上一版已交付 libfile_0f10e4610ed4819194366b01fcd3ad4a。本轮任务是让客户在创建维修工单前，明确本次会提交哪些附件、哪些需要调整。

## 用户问题与修复

原选择处理直接 slice(0,12)，第13个及以后文件无提示地丢失；超大和不支持类型要等工单创建后才被上传接口拒绝。本轮保留完整选择清单，显示总数、文件名、大小、逐项问题与“移除”。超过12个、空文件、类型与扩展名不匹配、图片超过10MB、视频超过100MB会在客户端阻止创建请求；移除或替换后恢复提交。重新选择明确为替换清单，不隐式追加。

移除后焦点移到下一项（末项则上一项），清空后回到选择控件；结果状态区提供文字提示，错误不仅用颜色表示。仍使用可聚焦的原生 file input，外观显示固定中文“选择或替换附件”，已选内容以下方清单为准，避免移除后原生 FileList 显示过时信息。大小向上保留两位小数，避免超10MB一个字节却被显示为10.0MB。已有表单输入、创建失败恢复、附件上传结果流程保留。

## 设计依据

2026-10-29 查阅 https://developer.apple.com/design/human-interface-guidelines/entering-data 及官方 `.md` 正文：在输入时验证并提供可修正反馈，说明需要的信息和无法继续的原因。将此原则用于现有 Web 表单，不增加装饰或业务模块。
