# D3 / D8 定损角色入口与写权限一致性

起点 af9c4ea。定损首页原来向所有角色显示开始/新建定损按钮，进行中任务统一标为“继续定损”；详情页却仅允许 admin、manager、engineer、technical_support 编辑。后端已全局禁止 viewer 写入，但创建、登记结果、完成三个接口原来只要求登录，权限比详情页宽。

本轮统一定损写能力为以上四个角色，复用 require_roles，保留 require_order_access 的工单范围检查。首页无写权限时隐藏开始/新建按钮，将进行中入口标为“查看”，显示当前账号可查看记录；详情与工作台复用同一前端能力判断。直接调用创建函数在读取数据或打开弹窗前即返回查看权限提示。只读查看、SOP 知识编辑角色及已有数据不变，无迁移。

验证：新增 7 个 API 角色场景，在隔离测试库给予相同工单访问范围；viewer/call_operator/finance/warehouse 可读但三个写接口均 403，拒绝后仍只有原定损单、结果为 pending、状态为 in_progress。engineer/technical_support/manager 可创建、登记和完成，admin 由既有集成流程覆盖。定损集成专项 20 项通过。新增 11 个前端行为测试，覆盖八种角色的首页 HTML 及直接创建入口拒绝；连同报价测试共 31 项通过。完整回归结果见交接记录。

影响：finance、warehouse 等非检测角色此前可能通过直接 API 创建或修改定损；现在明确拒绝，与原详情页权限一致。工单可见范围没有扩大，已有记录仍可在授权范围内查看。
