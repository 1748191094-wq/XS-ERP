# 第三阶段分析与完成情况

## 本阶段目标

第三阶段优先解决多人门店使用前的数据安全问题：没有登录保护、不同岗位权限未隔离、敏感操作不可追踪、数据库缺少经过校验的在线备份。

## 已完成

### 1. 登录与会话安全

- 首次启动由门店自行创建首位管理员，不在代码或数据库中预置明文密码。
- 本交付不包含业务数据库或预置管理员；首次启动由使用方自行创建管理员，密码只保存强哈希。
- 会话令牌使用高熵随机值，数据库只保存令牌 SHA-256 摘要。
- Cookie 设置 HttpOnly 和 SameSite=Strict；生产 HTTPS 可通过 `SESSION_COOKIE_SECURE=true` 强制 Secure。
- 写接口要求会话内独立 CSRF Token。
- 修改密码会撤销同账号的其他会话，停用账号或管理员重置密码会撤销该账号全部会话。
- 禁止停用或降级最后一名启用的管理员。

### 2. 角色权限

- 支持管理员、门店经理、前台、维修工程师、财务、库管和只读查看七类角色。
- 只读角色不能调用任何写接口。
- 财务接口仅管理员、门店经理和财务可访问。
- 库存写操作仅管理员、门店经理和库管可执行。
- 系统设置、账号管理和数据库备份仅管理员可访问。
- 操作审计仅管理员和门店经理可访问。
- 权限由后端执行，前端菜单隐藏只是辅助体验。

### 3. 操作审计

- 登录成功、登录失败、首次初始化以及所有已认证写操作均建立审计记录。
- 记录账号、请求路径、资源类型、结果、状态码、来源地址、客户端信息和请求编号。
- 不读取或保存请求正文，因此不会把密码、邮件授权码或客户提交内容复制到审计表。

### 4. 备份与恢复

- 使用 SQLite 在线备份接口生成一致性快照，兼容 WAL 模式下正在运行的系统。
- 备份临时文件关闭句柄后原子替换，已针对 Windows 文件锁行为修正并回归测试。
- 每个备份保存文件大小、SHA-256、完整性结果、创建人、说明及复验时间。
- 管理界面支持创建、下载和重新校验。
- 离线恢复脚本要求显式 `RESTORE` 确认，替换前自动建立恢复前保护副本。

## 实际验证

- 当前数据库迁移到 `0005_database_backups`。
- 隔离测试管理员登录返回 200，角色为 `admin`；测试账号不会写入交付目录。
- 实际业务数据库已创建一份备份并再次校验，结果为 `ok`。
- 浏览器已验证首次初始化、登录、管理员导航、账号管理和操作审计页面。
- 自动化测试结果为 5 项全部通过，覆盖原业务回归、认证授权、CSRF、审计和备份。

## 尚未完成

- 真实 SMTP、企业微信和顺丰仍需要正式账号及沙箱联调。
- DJI DAT、PX4 ULog、ArduPilot BIN 真实解析仍需要公开工具链或脱敏样本。
- 当前备份由管理员或命令行触发；Windows 计划任务/服务化定时备份和保留周期尚未配置。
- PostgreSQL 部署时需改用 PostgreSQL 原生备份工具，当前在线备份服务只支持 SQLite。
- 密码最低长度按门店要求设为 5 位；公网部署仍建议改为至少 10 位并增加登录失败限流或双因素认证。
