# 维修申请提交失败后的反馈与返回检查

起点 fbc7e01。原提交失败只显示一行状态文本，键盘焦点留在提交按钮，缺少结果含义和修改入口。本轮让客户知道输入仍保留、下一步如何检查。

实施前阅读 Apple 官方 Feedback 指南：https://developer.apple.com/design/human-interface-guidelines/feedback.md 。采用就近反馈、可访问文本、可执行恢复操作，保留自有品牌与表单结构。

## 改动

- 提交请求出错后显示“未能确认提交结果”卡片、原接口错误、输入与附件保留说明及网络中断时核对工单的提醒，不把通信失败说成确定未创建。
- 完成请求后聚焦关联标题与描述的错误区域，并滚动至易读位置；按钮“返回检查填写内容”将焦点带回设备选择，支持键盘。
- 保留原始表单、所选文件、原生必填校验及提交按钮；再次提交时清除旧错误，不自动发请求，不改变接口或业务数据。

## 验证

Vue 类型检查及生产构建通过，31项既有Node回归通过。真实 Chromium 隔离 API fixture 的维修申请和服务进度脚本通过320/390/1440px；新增断言覆盖错误区域焦点、附件保留、键盘返回设备选择且不额外创建工单，以及后续重提成功。最终滚动调整后重跑申请三宽通过。

实际查看手机390浅色、320深色和桌面1440错误状态截图，检查长中文文件名、错误卡片、恢复操作与底栏。初版错误聚焦后提交按钮局部被底栏遮挡，补充居中滚动并复核。浏览器使用隔离fixture，不是后端端到端。未专项验证真实读屏或系统移动浏览器。

## 剩余与交付

本轮无后端/迁移改动，未重跑后端全量。跨页草稿、附件补传/动态限额、后台A整体验收继续待办，B不展开。网络不确定结果仍需要核对，不宣称实现请求幂等恢复。无真实库/设备、推送或部署。

完整ZIP使用scripts/package_source.py从本地提交生成，包含运行说明、依赖、迁移、字体、静态资源和最新交接；校验CRC与逐文件SHA-256，排除真实配置/业务数据、依赖目录、缓存和.git。
