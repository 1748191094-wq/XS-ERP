# 客户客户端审计与落地说明

## 架构边界

- 主系统使用 FastAPI、SQLAlchemy、Alembic 和 SQLite，管理端沿用现有单页应用。
- 客户端使用 Vue 3、TypeScript、Vite、Pinia、Vue Router 和 Axios，由同一服务在 `/client` 提供。
- 客户账号与员工账号使用独立会话和权限边界，但业务仍写入同一套客户、设备、工单、报价和库存模型。
- 商城商品与维修库存分层；客户端不会获得采购价、供应商、库位或库存流水。

## 安全边界

- 会话存于 HttpOnly Cookie，写操作校验 CSRF Token。
- 客户详情、附件、维修、订单、回收和社区资源均在服务端校验归属。
- 下单价格和库存由服务端重算；关键提交使用幂等键或唯一约束。
- 上传文件校验大小、数量、MIME 和真实文件格式，并使用随机存储名。
- 未配置真实支付、邮件、物流或消息服务时明确显示未接入，不伪造成功结果。

## 无数据交付

- 迁移文件只定义表结构和必要的非业务默认项。
- 本交付不包含客户、设备、工单、报价、附件、商品、库存、订单、回收或社区业务记录。
- 首次启动创建空库，首次管理员初始化时填写商标/品牌名称。
- 测试使用隔离的临时数据，不写入交付目录或正式数据目录。

## 验证范围

- 覆盖管理员初始化、登录、权限、备份、客户会话、头像、商城、维修、订单、回收、社区、库存展示分级和上传校验。
- 覆盖 Alembic 升级、健康检查、管理端/客户端静态资源与 Windows 启动脚本。
- 真实外部支付、SMTP、企业消息、物流及公网高并发仍需由部署方使用自有账号完成联调。
