# 客户客户端一期审计与落地说明

审计日期：2026-08-23

## 开工前审计结论

- 实际主项目是本目录下的 FastAPI + SQLAlchemy 2 + Alembic + SQLite ERP，管理端为现有原生单页应用。
- 正式业务库是 `repair_management.db`。开工前版本为 `0027_email_template_library`，共有 58 张表，`PRAGMA integrity_check=ok`，WAL 已启用。
- 开工前核心数据为：客户 22、设备 9、维修工单 11、报价 34、附件 276。迁移后这些行数保持一致。
- 原提示词所称 `服务平台无人机平台-app_重构版.html` 在项目和附件临时目录中均不存在；现有 `member_client.html` 是局域网连接页，不是客户产品界面，因此没有虚构对该文件的复用。
- 可直接复用的核心链路为 `Customer → DroneDevice → RepairOrder → Quote → Shipment / FollowUp / Attachment`。客户端维修申请直接写入这条链路，并同步创建统一服务工单。
- 现有 `InventoryItem` 是维修物料表，包含采购成本与库位，不适合直接作为客户商品。商城使用独立的商品、SKU、图片和订单表，但仍位于同一个 SQLite 数据库中；SKU 可选关联库存物料，客户端响应永不暴露采购成本或内部库存关联。
- 客户账号与员工账号的权限边界不同。客户使用独立账号/会话表并绑定现有 `Customer`，不复用管理员角色，也不新建第二套数据库。
- 原员工登录已经具备 HttpOnly Cookie、PBKDF2-SHA256、SameSite 和 CSRF。客户登录沿用相同安全原则，增加失败锁定、会话撤销与客户操作日志。
- 项目没有配置 CORS。正式客户端由同一 FastAPI 服务在 `/client` 提供，API 保持同源；开发服务器只代理本地 API。
- 原附件接口主要按扩展名限制。客户上传另加声明 MIME、真实图片解码/格式核验、MP4/MOV `ftyp` 头核验、UUID 文件名、数量与大小限制。
- 当前目录没有可用 Git 元数据，不能依赖 `git diff` 或提交记录作为本次交付证据。

## 数据模型与迁移

迁移 `0028_client_platform` 新增 25 张表，覆盖：

- 客户账号、会话、地址、操作日志、客户附件与通知；
- 商品分类、商品、SKU、图片、购物车、零售订单及订单项；
- 回收机型参考价、估价规则、回收申请；
- 客户维修入口扩展；
- 社区板块、帖子、一级回复、点赞、收藏与举报。

迁移仅预置通用商品分类、社区板块和成色/功能系数规则，没有编造商品、回收机型参考价、客户、订单或支付数据。

历史 `0001_initial` 使用动态 `Base.metadata.create_all()`，导致空库继续回放旧增量迁移时产生重复列。`alembic/env.py` 现只对“完全空白且目标为 head”的数据库创建当前完整模型、写入相同非业务默认项并显式标记当前 head；任何已有数据库仍按正常 Alembic 迁移链升级。

## 客户端与管理端

- 客户端：Vue 3 + TypeScript + Vite + Pinia + Vue Router + Axios，生产构建输出到 `app/static/client`。
- 入口：`/client`；静态资源：`/client-assets`。
- 主导航：首页、商城、社区、工单、我的。维修与回收为首页核心入口，旧机换新保留为“即将上线”，没有伪装成已完成交易链路。
- 管理端：原工作台新增仅管理员可见的“客户平台”，集中处理客户账号、商城分类/商品/SKU/图片、订单状态、回收参考价/规则/正式报价、社区板块/帖子/举报。

## 关键安全边界

- 客户会话只存于 HttpOnly Cookie；CSRF Token 只放在当前标签页的 `sessionStorage`，不把登录令牌写入 `localStorage`。
- 每条客户详情、附件、维修、订单、回收、帖子编辑接口都在服务端校验账号/客户归属，避免按猜测 ID 越权。
- 下单价格和库存由服务端 SKU 重算；购物车显示值不能决定订单金额。
- 订单、维修、回收提交和发帖/评论使用幂等键或唯一约束，防止网络重试重复创建关键业务记录。
- 客户帖子按纯文本转义显示，不渲染用户 HTML。
- 支付目前明确为 `manual`。没有真实支付 Provider 时，只能由管理员凭实际流水人工确认，系统不会伪造支付成功。
- 回收估价只是后台规则计算的参考区间；正式报价必须由工作人员审核后提交，客户再接受或拒绝。
