# 项目结构与迁移边界

## 代码结构

- `legacy_quote_app.py`：保留的历史报价程序代码，仅供兼容和迁移参考。
- `app/`：FastAPI、SQLAlchemy、Alembic、服务层、管理端静态资源与报告模块。
- `client/`：Vue 3 + TypeScript 客户端源码。
- `scripts/`：启动、备份、恢复与可选旧库迁移工具。
- `tests/`：不含真实业务信息的自动化测试。

## 可复用设计

- 报价项目保存历史价格快照。
- SQLite 参数化查询和线程安全访问。
- PDF 使用临时文件与原子替换，避免失败时覆盖旧报告。
- 用户输入转义、中文字体发现、Excel 批量导入和后台邮件任务。

## 主要风险

- 历史单文件程序的界面、业务、数据库、PDF 和邮件耦合较高。
- 旧数据结构缺少完整的客户、设备、工单、库存、财务和审计实体。
- 历史金额、序列号、附件和时间字段可能存在不完整或格式不统一的情况。
- 迁移时不得推断缺失的收款、成本、客户归属或设备归属。
- 历史密钥、密码和本机配置不得进入新库或交付包。

## 无数据交付边界

- 本源码包不包含数据库、备份、日志、上传文件、历史 PDF、Excel、密钥或账号。
- 首次启动创建空库，只写入迁移版本和必要的非业务默认设置。
- 首次管理员初始化必须填写商标/品牌名称；系统不预置管理员。
- 旧库迁移仅在管理员明确提供自有数据源时执行，迁移前必须备份且不修改源文件。
